# 2차 튜닝 설계 — 정리된 외부 데이터 + 비율 유지 전처리 + 새 증강 (처음부터 학습하는 작은 ResNet)

작성 2026-11-19 · 마감 2026-11-20 · 대상 `01_coding/notebooks/final_model.ipynb`

## 1. 왜 하는가
1차 튜닝(R1~R12) 결과, Kaggle 사진(val)은 0.79~0.83을 맞혔지만 외부 실사진(val_ext)은 0.14~0.19로 거의 맞히지 못했다. 외부 데이터 혼합(R2)은 val_ext를 0.77까지 올렸는데도 clothes·shoes 하락 조건 때문에 기각됐다. 병목은 모델 크기가 아니라 **데이터 다양성과 품질**이다. 2차 튜닝의 목표는 외부 사진 정확도를 끌어올리는 것이다.

## 2. 목표 / 비목표 / 실패 조건
- 목표: 정리된 외부 데이터로 다시 튜닝해 val_avg(= (val + val_ext + val_hard) / 3)를 1차 최고(R9 0.502)보다 크게 올리고, 튜닝 과정을 노트북에 보여 준다.
- 비목표: 사전학습 모델, 모델 구조 변경(작은 ResNet 유지), 1차 실험 재실행, 무작위 자르기(RandomResizedCrop).
- 실패 조건: 학습과 검증/테스트 사진이 겹침, TEST를 두 번 이상 평가, 모델이 배경(AI Hub 아스팔트)으로 정답을 맞힘을 확인하지 않고 끝냄.

## 3. 이미 결정된 것 (사용자 결정)
- 데이터: 외부 클래스당 최대 2,000장. clothes는 외부 사진이 적어 Kaggle train에서 보충(합계 3,000). shoes 3,000장 유지.
- 데이터 정리(완료): AI Hub 유리는 병이 작거나(2% 미만) 색이 다르면 제외, 육안 검토 제외 목록, v2 cardboard 전부 제외. val_ext·test_ext·val_hard도 같은 기준으로 정리하고 같은 출처 미사용 사진으로 보충. 결과: `RESULT/data_split/{train_mix,val_ext,test_ext,val_hard}_clean.csv` (27,050 / 498 / 360 / 1,198장).
- 전처리: 사진 비율을 유지(긴 변을 맞추고 남는 곳을 채움).
- 증강: 무작위 자르기 제외. 좌우·상하반전, 회전, 색상 변화, 어둡게·흐림.
- 채택 규칙: clothes·shoes 조건 제거(val_ext에 두 클래스가 없고, shoes 검증 296장은 ±0.03이 흔한 흔들림이라 조건이 너무 엄격했음).
- 클래스 가중치 손실을 사다리 한 단계로 시험(유리·trash가 shoes·clothes의 절반 수준).
- 배경 외우기 점검: val_ext의 AI Hub metal이 유리·battery로 잘못 분류되는 비율을 따로 기록.
- Drive: `aihub_extra.zip`(04 폴더, 비공개), `extra_public.zip`(07 폴더), 교체된 `split_and_results.zip`, `val_hard_generated.zip` 업로드 완료.

## 4. 접근 방법
| 안 | 내용 | 장단점 |
|---|---|---|
| **A. 2차 사다리 추가 (선택)** | 1차 R1~R12 결과는 그대로 읽어 보여 주고, 정리된 데이터로 M1~M9를 새로 실행 | 튜닝 과정이 1차→2차로 이어져 보인다. 1차는 이전 데이터 기준이라 숫자를 직접 비교하지 않는다고 명시 |
| B. 사다리 전체 재실행 | R1~R12도 새 데이터로 다시 | 시간 2배 이상, 마감 불가 |
| C. 최종 설정만 학습 | 사다리 없이 한 번 | 튜닝 과정을 보여 달라는 요구와 맞지 않음 |

## 5. 2차 사다리 (한 번에 하나씩, 각 단계는 그때까지의 최고 설정에서 출발)
기준 설정 = 1차 최종 R9: 폭 48, 헤드 없음, 128px, 증강 어둡게·흐림, cosine, 30 epoch(patience 7), lr 1e-3, weight decay 1e-4, 배치 64.

| 단계 | 변경 | 확인하려는 것 |
|---|---|---|
| M1 | 학습 데이터 = 정리된 혼합 데이터(27,050장) | 새 기준점 |
| M2 | 비율 유지 전처리 | 찌그러짐 제거 효과 |
| M3 | 증강 + 좌우·상하반전 + 회전(±20°) | 방향 다양성 |
| M4 | 증강 + 색상 변화 | 조명·화이트밸런스 차이 |
| M5 | 증강 + TrivialAugmentWide | 자동 혼합 증강 |
| M6 | 클래스 가중치 손실 | 적은 클래스(유리·trash) 보정 |
| M7 | label smoothing 0.1 | 과신 억제 |
| M8 | 60 epoch, patience 10 | 데이터·증강이 늘어난 뒤의 epoch 효과 |
| M9 | 입력 160px | 해상도 |

예상 시간: 실험당 약 30~35분(데이터 2.3배), M8 약 65분, M9 약 50분 → 전체 약 5.5~6시간(Colab T4). `STOP_BEFORE`로 끊어 실행할 수 있고, 끊겨도 끝난 실험은 건너뛴다.

채택: val_avg가 현재 최고보다 +0.01 이상이면 채택. 클래스별 val 변화는 표로 함께 보여 준다(판정에는 쓰지 않음).

## 6. 세부 설계
- 데이터 셀: `*_clean.csv`를 읽어 `train_mix`, `val_ext`, `test_ext`, `val_hard`로 사용. 1차 분할(`train_mix.csv` 등)은 파일로 남기되 노트북 실행에는 쓰지 않는다. 정리 과정은 표(`extra_counts.csv`, `clean_report.csv`, 출처 비율)와 설명으로 보여 주고, 정리 스크립트는 `01_coding/tools/`에 기록으로 둔다(원본 AI Hub 196GB가 필요해 Colab에서는 실행 불가).
- Drive zip: `DATA_ZIPS`에 `aihub_extra.zip`, `extra_public.zip` 추가. 이미 압축을 푼 런타임이라도 zip 목록이 바뀌면 다시 푼다.
- 정규화 통계: 정리된 학습 데이터 2,000장(seed 42)으로 다시 계산해 `norm_stats_clean.json`에 고정.
- 비율 유지 캐시: 긴 변을 192px로 줄이고 짧은 쪽을 학습 데이터 평균색으로 채워 192×192로 저장. 기존 캐시와 다른 폴더(`192_lb`)에 저장.
- 증강 이름: `hflip`, `vflip`, `rot`, `color`, `trivial`, `dark_blur`(기존), `rrc`(1차 기록용으로만 남김).
- 클래스 가중치: 학습 데이터 클래스 장수 n_c로 w_c = sqrt(N / n_c), 평균이 1이 되게 정규화. 학습 손실에만 쓰고, 검증 손실은 가중치 없이 계산.
- 배경 점검 지표: `val_ext_by_source`(출처별 정확도), `aihub_metal_as_glass_battery`(val_ext의 AI Hub metal 중 battery·유리 3종으로 예측된 비율).
- 보고: 1차 표(읽기 전용, "이전 데이터 기준" 표기) → 2차 표·곡선 → epoch 효과(M7 vs M8) → 최종 설정 곡선 → 검증 평가(출처별 포함) → TEST 1회(정리된 test_ext).
- 최종 설정 = 2차 사다리가 끝난 뒤의 최고 실험.

## 7. 알려진 한계
- val_hard는 1차와 같은 방식으로 160px 정사각형으로 줄여 만든 손상 이미지라, 비율 유지 전처리와 달리 이미 찌그러져 있다(모든 2차 실험에 같아 비교에는 영향 없음).
- val_ext biological·trash는 49장(깨끗한 RealWaste 미사용 사진 부족).
- val_hard의 Kaggle 700장, 학습 데이터의 v2 biological·metal·plastic·trash는 육안 점검하지 않았다.
