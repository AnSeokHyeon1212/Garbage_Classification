### 4. 전처리 ① 정리와 크기 맞춤
단계마다 "무엇 → 왜"를 넣는다. 왼쪽 단을 이 네 줄로 채운다.

1. **중복 제거** (사진 지문 비교)
   - 이유: 같은 사진이 학습과 테스트에 함께 있으면 점수가 부풀려짐
2. **라벨 오류 제거** (직접 보고 제외)
   - 이유: 틀린 정답으로 학습하면 모델이 헷갈림. 예: 우유팩이 섞인 cardboard
3. **192 → 128px 크기 통일**
   - 이유: 묶어서 학습하려면 크기가 같아야 함. 128px는 속도와 정확도의 균형. 160px(M9)은 흐린 사진에서 오히려 낮았음
4. **정규화** (색 값을 평균 0, 퍼짐 1 근처로)
   - 이유: 값의 범위가 일정해야 학습이 안정적이고 빠름
   - 사전학습을 쓰지 않으므로 ImageNet 값 대신 **우리 학습 사진 27,050장의 평균·표준편차**를 사용
   - 우리 데이터는 밝은 배경이 많아 평균이 높음 (평균 [0.645, 0.621, 0.593])

- 오른쪽 그림(`preprocess_steps.png`) 안의 "정규화 후 (보기용으로 다시 펼침)"은 헷갈린다. 그림 아래 캡션으로 "정규화 후: 모델이 보는 값(색이 조금 달라 보임)"이라고 슬라이드 글자로 단다.

### 5. 전처리 ② 증강
- 쓴 증강의 이유를 이유 줄로 넣는다.
  - 반전·회전(±20°) → 쓰레기는 어느 방향으로든 놓임. 사진을 외우지 않게 함 (M3에서 +0.035)
  - 어둡게·흐림(둘 중 하나, 50%) → 그늘·실내 사진, 초점이 안 맞은 사진 대비
- 뺀 것의 이유를 정확히 쓴다.
  - 색 변화(M4) → 유리병 3색(갈색·초록·흰색)은 **색이 정답 단서**라 색을 흔들면 헷갈림
  - letterbox(M2) → 흐리거나 어두운 사진 정확도(val_hard) 0.766 → 0.640으로 하락
  - TrivialAugment(M5) → 변형이 너무 강해 오히려 하락 (0.848 → 0.836)
- 뺀 것 줄의 그림:
  - TrivialAugment가 두 칸 나오므로 하나만 남긴다.
  - letterbox 칸만 다른 사진(신발)이라는 것을 캡션으로 밝히거나, 같은 건전지 사진으로 통일할 수 없으면 그대로 두되 "letterbox: 비율 유지 + 빈 곳 채움" 캡션을 단다.

### 6. 튜닝 ① 방법 (val_avg 소개 포함)
- **val_avg 소개를 제대로 넣는다.** 왼쪽 상단:
  - 큰 키워드: `val_avg = (val + val_ext + val_hard) ÷ 3`
  - 이유 줄: 깨끗한 사진, 실제 환경 사진, 흐리거나 어두운 사진을 **모두** 잘 맞혀야 점수가 오름. 한 가지에만 맞춘 설정을 걸러냄
  - 규칙 줄: 한 번에 하나만 바꾸고, val_avg가 지금까지 최고보다 **0.01 이상** 오르면 반영
- 아래 세 카드(val / val_ext / val_hard)는 유지한다. 카드마다 "무엇을 보는지"를 붙인다.
  - val (2,327장): Kaggle 원본 검증용 → 기본 실력
  - val_ext (498장): 학습에 안 쓴 외부 실사 → 다른 촬영 환경
  - val_hard (1,198장): 흐림·어둡게·빛번짐 → 어려운 사진
- **흐름도 노드에 번호 + 바꾼 것 + 점수를 쓴다.** 반영은 초록 실선과 ✓, 반영 안 함은 회색 점선과 ✗.
  - 출발 설정: 폭 48 · cosine 학습률 · 어둡게/흐림 증강 · 30 epoch
  - M1 정리한 혼합 데이터 0.813 ✓
  - M2 비율 유지(letterbox) 0.776 ✗
  - M3 반전·회전 0.848 ✓
  - M4 밝기·색 변화 0.845 ✗
  - M5 TrivialAugment 0.836 ✗
  - M6 클래스 가중치 0.842 ✗
  - M7 라벨 스무딩 0.857 ✗
  - M8 epoch 30→60 0.877 ✓
  - M9 입력 160px 0.860 ✗
  - 최종 M8
- M4~M7은 **M3에서 각각 따로 갈라지는 가지**로 그린다. 지금은 M4→M5→M6→M7이 줄줄이 이어져 순서대로 진행한 것처럼 보인다. 세로로 쌓거나 M3에서 부채꼴로 뻗게 한다.

### 9. 모델 — 크기 변화를 보여 준다
- 상자마다 **사진 크기 × 채널 수**를 적는다. 상자의 가로세로는 오른쪽으로 갈수록 작게, 두께감(색 농도나 테두리)은 진하게 그린다.

  | 상자 | 크기 | 채널 |
  |---|---|---|
  | 입력 | 128×128 | 3 (RGB) |
  | 줄기 (3×3 합성곱, stride 2) | 64×64 | 48 |
  | 1단계 | 64×64 | 48 |
  | 2단계 | 32×32 | 96 |
  | 3단계 | 16×16 | 192 |
  | 4단계 | 8×8 | 384 |
  | 평균 풀링 | 1×1 | 384 |
  | Linear | — | 12 (클래스 점수) |

- 흐름도 위에 한 줄: **"사진은 점점 작아지고, 특징(채널)은 점점 많아진다"**
- 흐름도 아래 작은 글씨:
  - 1~4단계는 각각 잔차 블록 2개
  - 2~4단계 첫 블록에서 크기 절반·채널 두 배
- 왼쪽 키워드는 유지하되 이유 줄을 붙인다.
  - 파라미터 629만 개 → 처음부터 학습하므로 작게 설계
  - AdamW · cosine → 학습률을 점점 줄여 마지막에 안정적으로 수렴
