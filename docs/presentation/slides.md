# 발표 슬라이드 설계: 쓰레기 이미지 12종 분류

- 발표 시간: 약 7분 55초 (최대 10분), 슬라이드 13장 + 예비 1장 (1차 검토 반영)
- 모든 숫자는 `README.md`와 `revision_prompt.md`(1차 검토)에 있는 값만 쓴다.
- 이 문서를 새 대화창에 붙여 넣으면 PPTX를 만들 수 있다. 맨 아래 "새 대화창 프롬프트"를 함께 쓴다.

## 1. 디자인 규칙

색·간격 규칙은 getdesign.md의 디자인 참고 문서에서 영감을 받았다. 슬라이드에는 브랜드 이름이나 로고를 넣지 않는다.

### 1-1. 색 토큰 (그래프 PNG와 같은 값)

| 역할 | 색 |
|---|---|
| 배경 | `#FFFFFF` |
| 면(카드 안쪽 강조 면, 표 머리) | `#FAFAFA` |
| 본문 글자 | `#171717` |
| 보조 글자 | `#707070` |
| 3차 글자(캡션·쪽 번호) | `#9A9A9A` |
| 선·테두리 | `#DFDFDF` |
| 주 색(반영·최종·강조) | `#3ECF8E` |
| 진한 주 색(큰 숫자, 최종 막대 테두리, 선 그래프의 val) | `#24B47E` |
| 반영 안 함 | `#C7C7C7` |
| 보조 데이터(val_ext) | `#644FC1` |
| 경고·한계 강조(결론의 약점 숫자에만) | `#FF2201` |

### 1-2. 글꼴과 크기
- 글꼴: Pretendard. 제목은 SemiBold, 본문은 Regular. 없으면 Noto Sans KR(현재 PPTX는 Noto Sans KR, 제목 Bold).
- 크기: 제목 32pt, 화면 키워드 20pt, 이유 줄 14pt `#707070`, 캡션 12pt, 큰 숫자 60pt `#24B47E`.
- 키워드마다 "무엇을 → 왜"가 보이게, 큰 키워드 아래에 이유 줄을 붙인다. 화면 문장은 길게 쓰지 않는다.
- 그림 안 글자가 10pt 이하로 작아지면 그림 아래에 핵심 캡션을 슬라이드 글자로 다시 쓴다.

### 1-3. 모양
- 카드: 흰 바탕, 1px `#DFDFDF` 테두리, 모서리 12px, 그림자 없음.
- 그라데이션을 쓰지 않는다.
- 주 색은 한 장에 한 곳만 쓴다(큰 숫자 또는 핵심 도형 하나).
- 아이콘: Google Material Symbols Rounded, 색 `#171717`. 슬라이드마다 이름을 지정했다. 제목 왼쪽에 작게 둔다.
- 여백: 슬라이드 가장자리 여백을 넉넉히(약 0.6in), 요소 사이 간격을 일정하게 둔다.
- 그래프 PNG는 제목이 없다. 슬라이드 제목이 그 역할을 한다. 그래프는 흰 카드 안에 넣는다.
- 기존 사진 그림 4개(`source_examples`, `preprocess_steps`, `aug_used`, `aug_rejected`)는 그림 안에 작은 제목 글자가 있다. 그대로 쓰되 카드 안에 넣고, 위쪽 제목 글자가 거슬리면 위를 조금 잘라도 된다.

### 1-4. 슬라이드 공통 틀
- 위: 아이콘 + 제목(32pt).
- 가운데: 화면 키워드(20pt) + 이유 줄(14pt)과 그림.
- 오른쪽 아래: 쪽 번호(12pt, `#9A9A9A`).
- 발표 대본은 화면에 넣지 않고 발표자 노트에 넣는다.

## 2. 슬라이드

> 1차 검토(`revision_prompt.md`)를 반영한 14장 구성이다. PPTX는 `01_coding/tools/build_slides_pptx.py`로 만든다(`python 01_coding/tools/build_slides_pptx.py`).
> 표기: **키워드**(20pt) 아래 `→` 줄은 이유 줄(14pt `#707070`)이다.

### 슬라이드 1. 표지
- **제목**: 쓰레기 사진 12종 분류
- **부제**: 사전학습 없이 직접 만든 CNN(SmallResNet)
- **그림**: 클래스마다 학습 사진 1장(Kaggle)을 정사각형으로 잘라 6×2 띠로 놓고, 사진 아래에 클래스 이름(12pt `#9A9A9A`). 결과 숫자·팀명·이름·날짜는 넣지 않는다.
- **아이콘**: `recycling`
- **발표 대본**: 안녕하세요. 저희는 쓰레기 사진 한 장을 보고 12종류 중 무엇인지 맞히는 모델을 만들었습니다. 사전학습 모델 없이 작은 CNN인 SmallResNet을 직접 구현해서 처음부터 학습했습니다.
- **시간**: 20초

### 슬라이드 2. 목차
- **제목**: 목차
- **그림**: 번호 카드 5개(01 데이터 · 02 전처리 · 03 튜닝 · 04 모델·결과 · 05 결론)
- **아이콘**: `list`
- **발표 대본**: 발표는 다섯 부분입니다. 데이터를 어떻게 모으고 다듬었는지, 튜닝을 어떤 규칙으로 했는지, 최종 모델과 결과, 그리고 배운 점과 한계 순서로 말씀드리겠습니다.
- **시간**: 15초

### 슬라이드 3. 데이터
- **제목**: 데이터: 9개 출처를 모으다
- **화면 키워드**(위쪽 세 칸)
  1. **깨끗한 배경만 학습하면 실제 사진은 14~19%** → Kaggle 사진은 단색 배경 → 바닥·매립지 사진을 거의 못 맞힘
  2. **9개 출처 27,050장** → 아스팔트·매립지·실내 등 촬영 환경이 다른 사진을 섞음
  3. **불균형 8.8배 → 2.4배** → 가장 많은 클래스와 적은 클래스의 차이를 줄임 (clothes 5,325 vs brown-glass 607 → 외부 데이터로 보충)
- **그림**: 왼쪽 카드에 `source_examples.png`의 사진 10장을 영문 라벨 없이 잘라 2×5로 놓고, 사진마다 한국어 출처명(Kaggle 원본, AI Hub 직접 촬영, RealWaste 매립지, TriCascade, 생활 쓰레기(실제 환경), Garbage V2, 신발 제품 사진, 생활 쓰레기(기본 배경), 다양한 금속, clothing 옷·신발). 오른쪽 카드에 `class_counts.png`.
- **아이콘**: `dataset`
- **발표 대본**: 처음에는 Kaggle 사진만 학습했는데, 대부분 깨끗한 배경 위 물건이라 바닥이나 매립지에서 찍은 외부 사진은 0.14에서 0.19밖에 맞히지 못했습니다. 그래서 촬영 환경이 다른 9개 출처를 모아 27,050장으로 정리했습니다. 덕분에 가장 많은 클래스와 적은 클래스의 차이도 8.8배에서 2.4배로 줄었습니다.
- **시간**: 50초

### 슬라이드 4. 전처리 ① 정리와 크기
- **제목**: 전처리 ① 정리와 크기 맞춤
- **화면 키워드**(왼쪽 50%)
  1. **중복 제거 (사진 지문 비교)** → 같은 사진이 학습과 테스트에 함께 있으면 점수가 부풀려짐
  2. **라벨 오류 제거 (직접 보고 제외)** → 틀린 정답으로 학습하면 모델이 헷갈림. 예: 우유팩이 섞인 cardboard
  3. **192 → 128px 크기 통일** → 크기가 같아야 묶어서 학습 · 128px는 속도와 정확도의 균형 / 160px(M9)은 흐린 사진에서 오히려 낮았음
  4. **정규화 (색 값을 평균 0, 퍼짐 1 근처로)** → 값의 범위가 일정해야 학습이 안정적이고 빠름 / ImageNet 값 대신 우리 학습 사진 27,050장의 평균·표준편차 사용
- **그림**: 오른쪽 50% `preprocess_steps.png`, 아래 캡션 "정규화 후: 모델이 보는 값(색이 조금 달라 보임)"
- **아이콘**: `cleaning_services`
- **발표 대본**: 먼저 사진마다 지문을 만들어 거의 같은 사진을 지웠습니다. 같은 사진이 학습과 테스트에 함께 있으면 점수가 부풀려지기 때문입니다. 라벨과 맞지 않는 사진도 직접 보고 뺐고, 모든 사진을 192px로 맞춘 뒤 모델에는 128px로 넣고 정규화했습니다. 정규화 값은 사전학습을 쓰지 않으므로 ImageNet 값 대신 우리 학습 사진 27,050장의 평균과 표준편차를 썼습니다. 우리 데이터는 밝은 배경이 많아 평균이 높습니다(평균 0.645, 0.621, 0.593).
- **시간**: 40초

### 슬라이드 5. 전처리 ② 증강
- **제목**: 전처리 ② 증강: 쓴 것과 뺀 것
- **화면 키워드**
  - 쓴 것(위 카드, 테두리 `#3ECF8E`)
    1. **반전·회전(±20°)** → 쓰레기는 어느 방향으로든 놓임. 사진을 외우지 않게 함 (M3에서 +0.035)
    2. **어둡게·흐림(둘 중 하나, 50%)** → 그늘·실내 사진, 초점이 안 맞은 사진 대비
  - 뺀 것(아래 카드)
    1. **색 변화(M4)** → 유리병 3색(갈색·초록·흰색)은 색이 정답 단서라 색을 흔들면 헷갈림
    2. **letterbox(M2)** → 흐리거나 어두운 사진 정확도(val_hard) 0.766 → 0.640으로 하락
    3. **TrivialAugment(M5)** → 변형이 너무 강해 오히려 하락 (0.848 → 0.836)
- **그림**: 카드 오른쪽에 `aug_used.png` / `aug_rejected.png`(두 번째 TrivialAugment 칸을 잘라 4칸). letterbox 칸 아래 캡션 "letterbox: 비율 유지 + 빈 곳 채움 (신발 사진)".
- **아이콘**: `flip`
- **발표 대본**: 증강은 학습할 때만 사진마다 무작위로 넣었습니다. 쓰레기는 어느 방향으로든 놓이니까 반전과 회전을 넣었고, 그늘이나 초점이 안 맞은 사진에 대비해 어둡게와 흐림을 넣었습니다. 반대로 색 변화는 뺐는데, 유리병 세 종류는 색이 바로 정답 단서이기 때문입니다. 비율을 유지하는 letterbox도 val_hard가 0.766에서 0.640으로 떨어져서 뺐습니다. TrivialAugment는 변형이 너무 강해 0.848에서 0.836으로 떨어져서 뺐습니다.
- **시간**: 40초

### 슬라이드 6. 튜닝 ① 방법
- **제목**: 튜닝 ① 한 번에 하나씩
- **화면 키워드**(왼쪽 위): **val_avg = (val + val_ext + val_hard) ÷ 3** → 깨끗한 사진, 실제 환경 사진, 흐리거나 어두운 사진을 모두 잘 맞혀야 점수가 오름. 한 가지에만 맞춘 설정을 걸러냄. 규칙 줄(14pt `#171717`): 한 번에 하나만 바꾸고, val_avg가 지금까지 최고보다 **0.01 이상** 오르면 반영
- **검증 셋 카드 3개**(왼쪽 아래): val (2,327장) · Kaggle 원본 검증용 → 기본 실력 / val_ext (498장) · 학습에 안 쓴 외부 실사 → 다른 촬영 환경 / val_hard (1,198장) · 흐림·어둡게·빛번짐 → 어려운 사진
- **그림**: PPT 도형 흐름도(오른쪽).
  - 줄기(초록 실선, ✓): 출발 설정(폭 48 · cosine 학습률 · 어둡게/흐림 증강 · 30 epoch) → M1 정리한 혼합 데이터 0.813 ✓ → M3 반전·회전 0.848 ✓ → M8 epoch 30→60 0.877 ✓ → 최종 M8
  - 가지(회색 점선, ✗): M1에서 M2 비율 유지(letterbox) 0.776 ✗, M3에서 **각각 따로** M4 밝기·색 변화 0.845 ✗ · M5 TrivialAugment 0.836 ✗ · M6 클래스 가중치 0.842 ✗ · M7 라벨 스무딩 0.857 ✗(세로 빗 모양), M8에서 M9 입력 160px 0.860 ✗
- **아이콘**: `tune`
- **발표 대본**: 튜닝은 한 단계에 한 가지만 바꿨고, 점수가 지금까지 최고보다 0.01 이상 오를 때만 반영했습니다. 점수는 val_avg로, Kaggle 검증 사진, 학습에 안 쓴 외부 실사 사진, 그리고 흐림·어둡게·빛번짐을 입힌 어려운 사진, 이 세 셋의 평균입니다. 그림에서 초록 실선이 반영된 단계, 회색 점선이 시험만 하고 버린 단계입니다. M4부터 M7은 모두 M3 설정에서 하나씩 따로 바꿔 본 것입니다.
- **시간**: 40초

### 슬라이드 7. 튜닝 ② 결과
- **제목**: 튜닝 ② 두 번 크게 올랐다
- **화면 키워드**
  1. **M3 반전·회전 +0.035** → 사진을 외우던 문제가 줄어듦
  2. **M8 epoch 30→60 +0.029** → 30 epoch에서는 아직 오르는 중이었음
  3. **나머지는 기각** → 0.01 기준에 못 미치거나 하락
- **그림**: `ladder_val_avg.png`(M1 출발점은 진회색 `#707070`, 반영 M3·M8만 초록, x축 이름은 6번과 같음). 아래 작은 글씨 "y축은 0.70부터 시작".
- **아이콘**: `bar_chart`
- **발표 대본**: 막대에서 초록이 반영된 단계입니다. 가장 크게 오른 건 M3의 반전·회전 증강으로 +0.035, 그 다음이 M8에서 epoch을 30에서 60으로 늘린 +0.029였습니다. 라벨 스무딩 같은 나머지 시도는 0.01 기준에 못 미치거나 오히려 떨어져서 기각했습니다. M1은 출발점이라 회색으로 표시했습니다.
- **시간**: 35초

### 슬라이드 8. 튜닝 ③ 학습 곡선
- **제목**: 튜닝 ③ 학습 곡선으로 본 변화
- **화면 키워드**(위쪽 세 칸)
  1. **M1: train 1.0 / val 0.83 → 외움** → 차이 0.168 → 반전·회전을 넣은 M3는 0.069로 줄어듦
  2. **M3부터 함께 오름** → 반전·회전 증강으로 train과 val이 같이 오름
  3. **M8은 epoch 50 저장** → 검증 점수((val+val_ext)/2)가 가장 높았던 epoch의 가중치를 저장
- **그림**: `curves_m1_m3_m8.png` 전체 너비
- **아이콘**: `show_chart`
- **발표 대본**: 왼쪽 M1은 학습 정확도가 1.0까지 오르는데 val은 0.83에서 멈춥니다. 사진을 통째로 외운 겁니다. 반전·회전을 넣은 M3부터는 학습과 검증이 함께 오르고, M8은 60 epoch 중 기준 점수가 가장 좋았던 epoch 50의 가중치를 저장했습니다. M1의 train과 val 차이는 0.168이었는데 M3에서는 0.069로 줄어, 증강이 과적합을 줄였다는 근거가 됩니다.
- **시간**: 40초

### 슬라이드 9. 모델
- **제목**: 모델: SmallResNet 직접 구현(사전학습 없음)
- **화면 키워드**(위쪽 세 칸)
  1. **파라미터 629만 개** → 처음부터 학습하므로 작게 설계
  2. **잔차 블록 4단계 48→384** → 2~4단계마다 크기는 절반, 채널은 두 배
  3. **AdamW · cosine** → 학습률을 점점 줄여 마지막에 안정적으로 수렴
- **그림**: 한 줄 "사진은 점점 작아지고, 특징(채널)은 점점 많아진다" 아래 PPT 도형 블록 8개. 정사각형이 오른쪽으로 갈수록 작아지고, 채움은 회색 단계로 진해지며 테두리가 굵어진다. Linear만 초록 테두리. 블록 아래 라벨: 입력 128×128 × 3 (RGB) / 줄기 3×3 합성곱, stride 2, 64×64 × 48 / 1단계 64×64 × 48 / 2단계 32×32 × 96 / 3단계 16×16 × 192 / 4단계 8×8 × 384 / 평균 풀링 1×1 × 384 / Linear 12 (클래스 점수). 맨 아래 작은 글씨 "1~4단계는 각각 잔차 블록 2개", "2~4단계 첫 블록에서 크기 절반·채널 두 배".
- **아이콘**: `account_tree`
- **발표 대본**: 모델은 작은 ResNet을 torch로 직접 만들었고, 사전학습 가중치는 쓰지 않았습니다. 잔차 블록 네 단계를 지나며 채널이 48에서 384까지 늘고, 평균 풀링 뒤 Linear 하나로 12개 클래스 점수를 냅니다. 파라미터는 6,289,212개이고, AdamW와 cosine 학습률로 학습해 가장 좋은 epoch을 저장했습니다. 사진 크기는 128에서 8까지 작아지고, 채널은 3에서 384까지 늘어납니다.
- **시간**: 35초
