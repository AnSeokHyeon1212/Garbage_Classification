# 발표 슬라이드 설계: 쓰레기 이미지 12종 분류

- 발표 시간: 약 7분 10초 (최대 10분), 슬라이드 11장 + 예비 1장
- 모든 숫자는 `README.md` 값만 쓴다. 예외는 예비 슬라이드의 출력층 실험(Linear 0.878 vs 은닉층 2개 0.875) 하나다.
- 이 문서를 새 대화창에 붙여 넣으면 PPTX를 만들 수 있다. 맨 아래 "새 대화창 프롬프트"를 함께 쓴다.

## 1. 디자인 규칙

색·간격 규칙은 getdesign.md의 디자인 참고 문서에서 영감을 받았다. 슬라이드에는 브랜드 이름이나 로고를 넣지 않는다.

### 1-1. 색 토큰 (그래프 PNG와 같은 값)

| 역할 | 색 |
|---|---|
| 배경 | `#FFFFFF` |
| 면(카드 안쪽 강조 면, 표 머리) | `#FAFAFA` |
| 본문 글자 | `#171717` |
| 보조 글자 | `#707070` |
| 3차 글자(캡션·쪽 번호) | `#9A9A9A` |
| 선·테두리 | `#DFDFDF` |
| 주 색(반영·최종·강조) | `#3ECF8E` |
| 진한 주 색(큰 숫자, 최종 막대 테두리, 선 그래프의 val) | `#24B47E` |
| 반영 안 함 | `#C7C7C7` |
| 보조 데이터(val_ext) | `#644FC1` |
| 경고·한계 강조(결론의 약점 숫자에만) | `#FF2201` |

### 1-2. 글꼴과 크기
- 글꼴: Pretendard. 제목은 SemiBold, 본문은 Regular. 없으면 Noto Sans KR.
- 크기: 제목 32pt, 화면 키워드 20pt, 캡션 12pt, 큰 숫자 60pt `#24B47E`.

### 1-3. 모양
- 카드: 흰 바탕, 1px `#DFDFDF` 테두리, 모서리 12px, 그림자 없음.
- 그라데이션을 쓰지 않는다.
- 주 색은 한 장에 한 곳만 쓴다(큰 숫자 또는 핵심 도형 하나).
- 아이콘: Google Material Symbols Rounded, 색 `#171717`. 슬라이드마다 이름을 지정했다. 제목 왼쪽에 작게 둔다.
- 여백: 슬라이드 가장자리 여백을 넉넉히(약 0.6in), 요소 사이 간격을 일정하게 둔다.
- 그래프 PNG는 제목이 없다. 슬라이드 제목이 그 역할을 한다. 그래프는 흰 카드 안에 넣는다.
- 기존 사진 그림 4개(`source_examples`, `preprocess_steps`, `aug_used`, `aug_rejected`)는 그림 안에 작은 제목 글자가 있다. 그대로 쓰되 카드 안에 넣고, 위쪽 제목 글자가 거슬리면 위를 조금 잘라도 된다.

### 1-4. 슬라이드 공통 틀
- 위: 아이콘 + 제목(32pt).
- 가운데: 화면 키워드(최대 3줄, 20pt)와 그림.
- 오른쪽 아래: 쪽 번호(12pt, `#9A9A9A`).
- 발표 대본은 화면에 넣지 않고 발표자 노트에 넣는다.

## 2. 슬라이드

### 슬라이드 1. 제목
- **제목**: 쓰레기 사진 12종 분류
- **화면 키워드**
  1. 사전학습 없이 처음부터 학습
  2. 직접 만든 작은 ResNet
- **큰 숫자**: `0.8823` (아래 캡션: test 정확도)
- **그림**: 없음. 가운데 정렬, 큰 숫자를 제목 아래에 둔다.
- **아이콘**: `recycling`
- **발표 대본**: 안녕하세요. 저희는 쓰레기 사진 한 장을 보고 12종류 중 무엇인지 맞히는 모델을 만들었습니다. 사전학습 모델 없이 작은 ResNet을 직접 구현해서 처음부터 학습했고, 최종 test 정확도는 0.8823입니다.
- **시간**: 20초

### 슬라이드 2. 목차
- **제목**: 목차
- **화면 키워드**
  1. 데이터 · 전처리
  2. 튜닝 · 모델 · 결과
  3. 결론
- **큰 숫자**: 없음
- **그림**: 없음. 5개 항목(데이터 · 전처리 · 튜닝 · 모델·결과 · 결론)을 왼쪽에서 오른쪽으로 번호 카드 5개로 늘어놓는다. 카드 안은 번호(01~05)와 이름만 쓴다. 화면 키워드 3줄 대신 이 카드 5개를 써도 된다.
- **아이콘**: `list`
- **발표 대본**: 발표는 다섯 부분입니다. 데이터를 어떻게 모으고 다듬었는지, 튜닝을 어떤 규칙으로 했는지, 최종 모델과 결과, 그리고 배운 점과 한계 순서로 말씀드리겠습니다.
- **시간**: 15초

### 슬라이드 3. 데이터
- **제목**: 데이터: 9개 출처를 모으다
- **화면 키워드**
  1. Kaggle만 학습 → 외부 0.14~0.19
  2. 9개 출처 27,050장
  3. 불균형 8.8배 → 2.4배
- **큰 숫자**: 없음
- **그림**: 왼쪽 `source_examples.png`(출처별 예시 사진 10장), 오른쪽 `class_counts.png`(클래스별 학습 장수 가로 막대). 두 그림을 각각 카드에 넣어 반씩 나눈다. 키워드는 그림 위 한 줄 띠로 둔다.
- **아이콘**: `dataset`
- **발표 대본**: 처음에는 Kaggle 사진만 학습했는데, 대부분 깨끗한 배경 위 물건이라 바닥이나 매립지에서 찍은 외부 사진은 0.14에서 0.19밖에 맞히지 못했습니다. 그래서 촬영 환경이 다른 9개 출처를 모아 27,050장으로 정리했습니다. 덕분에 가장 많은 클래스와 적은 클래스의 차이도 8.8배에서 2.4배로 줄었습니다.
- **시간**: 50초

### 슬라이드 4. 전처리 ① 정리와 크기
- **제목**: 전처리 ① 정리와 크기 맞춤
- **화면 키워드**
  1. 중복 제거(사진 지문 비교)
  2. 라벨 오류 제거
  3. 192→128px · 정규화
- **큰 숫자**: 없음
- **그림**: 오른쪽 `preprocess_steps.png`(원본 → 192 → 128 → 정규화, 신발·건전지 두 줄). 화면 오른쪽 약 60%를 차지한다. 키워드는 왼쪽에 세로로.
- **아이콘**: `cleaning_services`
- **발표 대본**: 먼저 사진마다 지문을 만들어 거의 같은 사진을 지웠습니다. 같은 사진이 학습과 테스트에 함께 있으면 점수가 부풀려지기 때문입니다. 라벨과 맞지 않는 사진도 직접 보고 뺐고, 모든 사진을 192px로 맞춘 뒤 모델에는 128px로 넣고 정규화했습니다.
- **시간**: 40초

### 슬라이드 5. 전처리 ② 증강
- **제목**: 전처리 ② 증강: 쓴 것과 뺀 것
- **화면 키워드**
  1. 쓴 것: 반전 · 회전 · 어둡게/흐림
  2. 뺀 것: 색 변화(색이 정답 단서)
  3. 뺀 것: letterbox 0.766→0.640
- **큰 숫자**: 없음
- **그림**: 위 `aug_used.png`(쓴 증강 6칸), 아래 `aug_rejected.png`(뺀 방법 5칸). 둘 다 전체 너비. 위 카드 왼쪽에 "쓴 것", 아래 카드 왼쪽에 "뺀 것" 작은 라벨(12pt)을 붙인다. 위 카드 테두리만 주 색 `#3ECF8E`, 아래 카드는 `#DFDFDF`.
- **아이콘**: `flip`
- **발표 대본**: 증강은 학습할 때만 사진마다 무작위로 넣었습니다. 쓰레기는 어느 방향으로든 놓이니까 반전과 회전을 넣었고, 그늘이나 초점이 안 맞은 사진에 대비해 어둡게와 흐림을 넣었습니다. 반대로 색 변화는 뺐는데, 유리병 세 종류는 색이 바로 정답 단서이기 때문입니다. 비율을 유지하는 letterbox도 val_hard가 0.766에서 0.640으로 떨어져서 뺐습니다.
- **시간**: 40초

### 슬라이드 6. 튜닝 ① 방법
- **제목**: 튜닝 ① 한 번에 하나씩
- **화면 키워드**
  1. 한 번에 하나만 바꾼다
  2. val_avg +0.01 이상이면 반영
  3. val_avg = 세 검증 셋 평균
- **큰 숫자**: 없음
- **그림**: PPT 도형으로 그리는 위→아래 흐름도(화면 오른쪽 약 55%).
  - 줄기: `출발 설정` → `M1 0.813` → `M3 0.848` → `M8 0.877` → `최종 M8`. 상자와 화살표는 주 색 `#3ECF8E` 실선(최종 상자만 테두리 `#24B47E`).
  - 가지(회색 `#C7C7C7` 점선, 상자 글자 `#707070`): M1에서 `M2 0.776`, M3에서 `M4 0.845` · `M5 0.836` · `M6 0.842` · `M7 0.857`, M8에서 `M9 0.860`.
  - 화면 왼쪽 아래에 세 검증 셋 설명 카드 3개를 세로로 둔다(12pt 캡션):
    - val: Kaggle 검증 2,327장
    - val_ext: 학습에 안 쓴 외부 실사 498장
    - val_hard: 흐림·어둡게·빛번짐 1,198장
- **아이콘**: `tune`
- **발표 대본**: 튜닝은 한 단계에 한 가지만 바꿨고, 점수가 지금까지 최고보다 0.01 이상 오를 때만 반영했습니다. 점수는 val_avg로, Kaggle 검증 사진, 학습에 안 쓴 외부 실사 사진, 그리고 흐림·어둡게·빛번짐을 입힌 어려운 사진, 이 세 셋의 평균입니다. 그림에서 초록 실선이 반영된 단계, 회색 점선이 시험만 하고 버린 단계입니다.
- **시간**: 40초

### 슬라이드 7. 튜닝 ② 결과

- **화면 키워드**
  1. M3 반전·회전 +0.035
  2. M8 epoch 30→60 +0.029
  3. 나머지는 기각
- **큰 숫자**: 없음
- **그림**: `ladder_val_avg.png` 전체 너비(M1~M9 val_avg 막대, 반영은 초록, 기각은 회색). 키워드는 그림 위 한 줄 또는 왼쪽 좁은 열.
- **아이콘**: `bar_chart`
- **발표 대본**: 막대에서 초록이 반영된 단계입니다. 가장 크게 오른 건 M3의 반전·회전 증강으로 +0.035, 그 다음이 M8에서 epoch을 30에서 60으로 늘린 +0.029였습니다. 라벨 스무딩 같은 나머지 시도는 0.01 기준에 못 미치거나 오히려 떨어져서 기각했습니다.
- **시간**: 35초

### 슬라이드 8. 튜닝 ③ 학습 곡선
- **제목**: 튜닝 ③ 학습 곡선으로 본 변화
- **화면 키워드**
  1. M1: train 1.0 / val 0.83 → 외움
  2. M3부터 함께 오름
  3. M8은 epoch 50 저장
- **큰 숫자**: 없음
- **그림**: `curves_m1_m3_m8.png` 전체 너비(M1 · M3 · M8 세 칸, train 검정 · val 초록 · val_ext 보라). 키워드 3줄을 각 칸 위에 하나씩 맞춰 놓아도 좋다.
- **아이콘**: `show_chart`
- **발표 대본**: 왼쪽 M1은 학습 정확도가 1.0까지 오르는데 val은 0.83에서 멈춥니다. 사진을 통째로 외운 겁니다. 반전·회전을 넣은 M3부터는 학습과 검증이 함께 오르고, M8은 60 epoch 중 기준 점수가 가장 좋았던 epoch 50의 가중치를 저장했습니다.
- **시간**: 40초

### 슬라이드 9. 모델
- **제목**: 모델: SmallResNet 직접 구현(사전학습 없음)
- **화면 키워드**
  1. 파라미터 629만 개
  2. 잔차 블록 4단계 48→384
  3. AdamW · cosine
- **큰 숫자**: 없음
- **그림**: PPT 도형으로 그리는 왼쪽→오른쪽 블록 도형(화면 아래 절반, 전체 너비).
  - `입력 3×128×128` → `줄기 48` → `1단계 48` → `2단계 96` → `3단계 192` → `4단계 384` → `평균 풀링` → `Linear 12`
  - 상자는 흰 카드(1px `#DFDFDF`). 단계 상자는 채널 수에 따라 높이를 조금씩 키운다. 마지막 `Linear 12` 상자만 주 색 `#3ECF8E` 테두리.
  - 단계 상자 아래 작은 캡션(12pt): "BasicBlock ×2, 잔차 연결".
- **아이콘**: `account_tree`
- **발표 대본**: 모델은 작은 ResNet을 torch로 직접 만들었고, 사전학습 가중치는 쓰지 않았습니다. 잔차 블록 네 단계를 지나며 채널이 48에서 384까지 늘고, 평균 풀링 뒤 Linear 하나로 12개 클래스 점수를 냅니다. 파라미터는 6,289,212개이고, AdamW와 cosine 학습률로 학습해 가장 좋은 epoch을 저장했습니다.
- **시간**: 35초

### 슬라이드 10. 결과와 과적합 점검
- **제목**: 결과와 과적합 점검
- **화면 키워드**
  1. test_ext 0.9028
  2. train−val 차이 0.10 → 가벼운 과적합
  3. 최다 혼동: 비슷한 쌍
- **큰 숫자**: `0.8823` (작은 캡션: test, 2,328장 1회 평가). 0.8823은 이 큰 숫자에만 쓰고 제목·키워드에서 반복하지 않는다.
- **그림**: 세 칸.
  - 왼쪽 위: 큰 숫자 카드.
  - 왼쪽 아래: `test_scores.png`(검증 vs TEST 막대 0.879/0.882, 0.922/0.903).
  - 오른쪽 절반: `confusion_test.png`(test 혼동행렬, 흰색→초록). 화면에서 white-glass→plastic 16, clothes→shoes 16, shoes→clothes 12, battery→metal 8 칸에 1px `#171717` 테두리 사각형을 겹쳐 그려 눈에 띄게 한다.
  - 자리가 되면 `final_curve_gap.png`를 왼쪽 아래에 `test_scores.png` 대신 또는 옆에 작게 넣는다. 좁으면 10a/10b로 나눈다(아래 참고).
- **아이콘**: `fact_check`
- **발표 대본**: 최종 TEST는 한 번만 했고, test 0.8823, 외부 실사 test_ext 0.9028이 나왔습니다. 과적합을 점검해 보면, 저장한 epoch에서 train이 0.982, val 0.879, test 0.882로 약 0.10 차이가 나서 가벼운 과적합은 있습니다. 하지만 검증과 TEST 점수가 거의 같아서 처음 보는 사진에도 일반화는 유지됩니다. 외부 사진은 val_ext 0.922에서 test_ext 0.903으로 약 0.02 낮지만 큰 차이는 아닙니다. 혼동행렬에서 가장 많이 틀린 쌍은 투명 유리→플라스틱 16장, 옷↔신발 16장·12장, 건전지→금속 8장으로, 눈으로 봐도 비슷한 것들입니다.
- **시간**: 70초
